## 0. このステップで作ったものを一言で

> マイページで、**自分の投稿をタイトル検索・ステータス絞り込み**で素早く見つけられるようにした。

投稿が増えても、「完成だけ見たい」「タイトルに『海辺』が入るものだけ探したい」といった操作ができるようになりました。

---

## 1. 全体の流れ

```
マイページ（/mypage）
        │
        ├─ 検索ボックスに入力 … wire:model.live.debounce.300ms="search"
        │       │  0.3秒待ってから
        │       ▼
        │   filteredStories() … title LIKE '%検索語%'
        │
        └─ ステータスを選択 … wire:model.live="statusFilter"
                │
                ▼
        filteredStories() … status で絞り込み（'all' なら絞らない）
                │
                ▼
        両方の条件を満たすストーリーだけ一覧表示
                │
                ├─ 投稿0件 →「まだ投稿がありません」
                ├─ 投稿はあるが条件に合うもの0件 →「条件に合う投稿がありません」
                └─ 1件以上 → カード一覧
```

## 3. やさしい解説（中学生レベル）

### 3.1 検索・絞り込み用の変数を2つ用意

```php
public string $search = '';

public string $statusFilter = 'all';
```

- `$search` … 検索ボックスに入力された文字
- `$statusFilter` … 選ばれたステータス（`all` / `complete` / `draft`）

Livewire では `public` の変数が画面と自動でつながります。

### 3.2 `filteredStories()` で条件を組み立てる

```php
private function filteredStories(): Collection
{
    $query = auth()->user()->stories()->with('image')->latest();

    if ($this->statusFilter !== 'all') {
        $query->where('status', $this->statusFilter);
    }

    if ($this->search !== '') {
        $query->where('title', 'like', '%'.$this->search.'%');
    }

    return $query->get();
}
```

基本はステップ13と同じ「自分のストーリーを新しい順に取得」です。その上で、

1. ステータスが `all` 以外なら → `where('status', ...)` で絞る
2. 検索語が空でなければ → `where('title', 'like', ...)` で絞る

**両方の条件がそろうと、両方とも満たすものだけ**残ります（AND条件）。

### 3.3 `LIKE` と `%` で部分一致検索

```php
$query->where('title', 'like', '%'.$this->search.'%');
```

検索語が `海辺` なら、実際には `title LIKE '%海辺%'` という条件になります。

- `LIKE` … 「〜のような」という部分一致検索
- `%` … 「ここは何文字でもOK」というワイルドカード

| パターン | 意味 |
| --- | --- |
| `%海辺%` | タイトルの**どこかに**「海辺」が含まれる |
| `海辺%` | **先頭**が「海辺」 |
| `%海辺` | **末尾**が「海辺」 |

マイページでは `%` + 検索語 + `%` にしているので、タイトルの途中でも見つかります。

※ 今回は**ストーリーのタイトル**だけを検索します。本文（`body`）やお題のタイトルは対象外です。

### 3.4 ステータス絞り込みは `'all'` のときスキップ

```php
if ($this->statusFilter !== 'all') {
    $query->where('status', $this->statusFilter);
}
```

- `'all'` … 条件を付けない（完成・散文の両方）
- `'complete'` … 完成だけ
- `'draft'` … 散文・アイデアだけ

「すべて」を選んだときは `if` に入らないので、ステータスでは絞りません。

### 3.5 空の表示を2種類に分ける

```php
'hasStories' => auth()->user()->stories()->exists(),
'stories' => $this->filteredStories(),
```

```blade
@if (! $hasStories)
    {{-- まだ投稿がありません --}}
@elseif ($stories->isEmpty())
    {{-- 条件に合う投稿がありません --}}
@else
    {{-- 一覧 --}}
@endif
```

| 状態 | 表示 |
| --- | --- |
| 投稿が1件もない | 「まだ投稿がありません」 |
| 投稿はあるが、検索・絞り込みに合うものがない | 「条件に合う投稿がありません」 |

ユーザーが「本当に何も書いていないのか」「絞り込みが厳しすぎるのか」を迷わないための工夫です。

### 3.6 `wire:model.live.debounce.300ms` の仕組み（詳しく）

検索ボックスにはこう書いています。

```blade
<flux:input
    wire:model.live.debounce.300ms="search"
    placeholder="タイトルを入力"
    icon="magnifying-glass"
    clearable
/>
```

これは「**検索ボックスに入力した文字を、PHP側の `$search` に送って、画面を更新する**」ための設定です。1つずつ分解します。

#### `wire:model` … 入力欄と変数をつなぐ（配線）

- 入力欄（画面）⇄ `$search`（PHP）が**双方向**につながる
- ユーザーが入力 → `$search` が変わる
- `$search` が変わる → 入力欄の表示も変わる

`wire:model` は Livewire の「**配線（はい線）**」です。

#### `.live` … 変わったらすぐ画面を更新

`.live` を付けると、`$search` が変わった瞬間にコンポーネントが再読み込みされ、`with()` → `filteredStories()` がもう一度動いて、**一覧が絞り込まれた状態で再表示**されます。

`.live` = 「**リアルタイム更新モード**」です。

#### `.debounce` … 入力が止まるのを待つ

`.live` だけだと、1文字打つたびに毎回サーバーへ問い合わせが走ります。「海辺」と打つと「海」で1回、「海辺」でまた1回、と**2回**通信してしまいます。

`.debounce` は「**まだ打っている最中は待つ。打つのを止めてから実行する**」仕組みです。

#### `.300ms` … 0.3秒待つ

- `ms` = ミリ秒（1秒 = 1000ms）
- `300ms` = **0.3秒**

流れ：

1. ユーザーが「海」と入力 → 0.3秒タイマー開始
2. すぐに「辺」も入力 → タイマーがリセット
3. 入力が止まる → 0.3秒経過
4. やっと検索が実行される

「海辺」と打っても、**最後に1回だけ**検索されます。

#### `="search"` … つなぐ先の変数名

PHP側の `public string $search = '';` を指します。

#### 部品の対応表

| 部品 | 役割 | たとえ |
| --- | --- | --- |
| `wire:model` | 入力欄と `$search` をつなぐ | 配線 |
| `.live` | 変わったら画面を更新 | リアルタイム反映 |
| `.debounce` | 連続入力中は待つ | 打ち終わるまで待つ |
| `.300ms` | 0.3秒待つ | 待ち時間の長さ |
| `="search"` | つなぐ変数名 | 送り先の名前 |

#### なぜ3つも付けるの？

| 設定 | ないとどうなる？ |
| --- | --- |
| `wire:model` なし | 入力しても `$search` に届かない |
| `.live` なし | 入力してもすぐ一覧が変わらない |
| `.debounce` なし | 1文字ごとにサーバーへ問い合わせて遅くなる |

3つ組み合わせることで、「**入力したらすぐ絞り込まれるけど、無駄な通信は減らす**」というバランスになります。

#### 実際の流れ（時系列）

「海辺の夕暮れ」を探す場合：

```
1. ユーザーが検索ボックスに「海」と入力
2. $search が「海」になる（まだ検索はしない）
3. 0.3秒タイマー開始
4. すぐに「辺」も入力される
5. $search が「海辺」に更新、タイマーがリセット
6. また0.3秒待つ
7. 入力が止まる
8. 0.3秒経過
9. Livewire がサーバーへ問い合わせ
10. filteredStories() が動く
    → where('title', 'like', '%海辺%')
11. 一覧が絞り込まれて画面に表示される
```

### 3.7 ステータス選択は `wire:model.live` のみ

```blade
<flux:select wire:model.live="statusFilter">
```

プルダウンは1回選ぶだけなので、`debounce` は不要です。選んだ瞬間に `.live` で一覧が更新されます。

## 4. 理解度チェック問題（4択・解答つき）

まずは選択肢を見て、自分で答えを考えてみましょう。解答と中学生レベルの解説は各問のすぐ下にあります。

### Q1. 検索ボックスの `wire:model.live.debounce.300ms="search"` の役割は？

- A. 検索語をデータベースから自動で削除する
- B. 入力のたびにすぐ更新し、300ミリ秒待ってから検索を実行する
- C. 300件までしか検索結果を表示しない
- D. ログインしていない人だけが検索できるようにする

**正解：B**

- `wire:model` … 入力欄と `$search` をつなぐ
- `.live` … 変わったらすぐ画面を更新
- `.debounce.300ms` … 入力が止まってから0.3秒待って実行

3つ合わせて「リアルタイムに絞り込むが、1文字ごとの無駄な通信は減らす」という動きになります。詳しい分解は 3.6 を参照。

引っかけ：A は削除の話、C は件数制限ではない、D は `auth` ミドルウェアの話です。

### Q2. `$query->where('title', 'like', '%'.$this->search.'%');` の意味は？

- A. タイトルが検索語と**完全一致**するストーリーだけを探す
- B. タイトルの**どこかに**検索語が含まれるストーリーを探す
- C. 本文（body）のどこかに検索語が含まれるストーリーを探す
- D. お題のタイトルで検索する

**正解：B**

`LIKE '%海辺%'` は「タイトルのどこかに `海辺` が含まれる」という条件です。`%` は「前後に何文字あってもOK」のワイルドカードです。

引っかけ：A は `=` の完全一致、C は `body` カラム、D は `image` のタイトル。今回はストーリーの `title` だけを検索しています。

### Q3. `statusFilter` が `'all'` のとき、クエリはどうなる？

- A. 完成したストーリーだけを取得する
- B. 散文・アイデアだけを取得する
- C. ステータスで絞り込まず、完成・散文の両方を取得する
- D. ストーリーを1件も取得しない

**正解：C**

```php
if ($this->statusFilter !== 'all') {
    $query->where('status', $this->statusFilter);
}
```

`'all'` のときはこの `if` に入らないので、ステータス条件は付きません。完成・散文の両方が表示されます。

### Q4. 「まだ投稿がありません」と「条件に合う投稿がありません」の出し分けで正しいのは？

- A. どちらも同じ条件（`$stories->isEmpty()`）で表示する
- B. 投稿が1件もないときは前者、投稿はあるが検索・絞り込みに合うものがないときは後者
- C. ログインしていないときだけ前者を表示する
- D. 検索ボックスに何か入力したときだけ後者を表示する

**正解：B**

- `!$hasStories` … 投稿が**1件もない**
- `$hasStories` かつ `$stories->isEmpty()` … 投稿はあるが**条件に合うものがない**

2段階で判定することで、ユーザーが状況を正しく理解できます。

引っかけ：A は前者だけでは区別できない、C はログインの話、D は入力の有無だけでは決まらない（ステータス絞り込みだけでも後者になり得る）。

### Q5. 検索語「海辺」とステータス「完成」を**同時に**選んだとき、表示されるのは？

- A. タイトルに「海辺」が含まれるストーリー**すべて**（完成・散文どちらも）
- B. 完成したストーリー**すべて**（タイトルは関係なし）
- C. タイトルに「海辺」が含まれ、**かつ**ステータスが完成のストーリーだけ
- D. お題のタイトルに「海辺」が含まれる完成ストーリーだけ

**正解：C**

検索とステータスは**両方**クエリに追加されます。

1. `status = complete`
2. `title LIKE '%海辺%'`

→ **両方を満たす**ストーリーだけが表示されます（AND条件）。

引っかけ：A はステータスを無視、B は検索を無視、D はお題タイトルでの検索（今回はしていない）。

### 5問のつながり（まとめ）

```
入力を待って検索（Q1）→ タイトルの部分一致（Q2）→ ステータス絞り込み（Q3）
→ 空の表示を2種類に分ける（Q4）→ 検索と絞り込みを同時に使える（Q5）
```

この5つがつながって「使いやすい検索・絞り込み」ができています。

# ステップ13 振り返り：マイページ / 自分の投稿一覧

このドキュメントは「文倉」開発ステップ13（マイページ `/mypage`）の振り返りです。
ステップ10の「お気に入り一覧」と対になる機能で、**自分が書いたストーリーをまとめて管理できる**ページを作りました。
やさしい解説（中学生レベル）と、理解度チェック問題（解答つき）を収録します。

---

## 0. このステップで作ったものを一言で

> ログインユーザーが、**自分のプロフィールと、自分が書いたストーリーを一覧で管理できる**マイページを作った。

お気に入り一覧（ステップ10）が「保存した話を読み返す」ページなら、マイページは「**自分が書いた話をまとめて見て、編集・削除する**」ページです。

---

## 1. 全体の流れ

```
ヘッダーの「マイページ」ボタン（ログイン時のみ表示）
        │  wire:navigate
        ▼
[門番] auth ミドルウェア …… 未ログインはログイン画面へ
        │
        ▼
/mypage（Livewire）
        │  with()
        ▼
自分のストーリーを新しい順に取得（お題画像もまとめて）
        │
        ▼
一覧表示
        ├─ プロフィール（名前・メール）を表示
        ├─ 各カードをクリック → 詳細ページへ
        ├─ 鉛筆ボタン → 編集ページへ
        └─ ゴミ箱ボタン → 確認ダイアログ → 削除（マイページにとどまる）
```

## 3. やさしい解説（中学生レベル）

### 3.1 「ログイン必須」の作り方

```php
Route::middleware('auth')->group(function () {
    Route::livewire('/mypage', 'pages::mypage')->name('mypage');
});
```

- `middleware`（ミドルウェア）＝ ページを表示する**前に通る関所**
- `'auth'` ＝ 「ログインしてる？」を確認する関所
- `->group(...)` ＝ 「この中のページ全部に、その関所を付ける」

マイページは「自分のプロフィール」と「自分の投稿」を見るページなので、ログインしていない人には見せられません。

### 3.2 自分のストーリーだけ取ってくる

```php
auth()->user()->stories()
    ->with('image')
    ->latest()
    ->get();
```

- `auth()->user()` ＝ 今ログインしている**自分**
- `->stories()` ＝ その人が**書いた**ストーリーたち
- `->with('image')` ＝ お題の情報も**まとめて**持ってくる（後述）
- `->latest()` ＝ **新しいものが先**
- `->get()` ＝ 実際に取ってくる

お気に入り一覧（`bookmarks()`）とは違い、ここでは「**自分が書いた話**」を取ります。他人のストーリーは最初から混ざりません。

### 3.3 N+1問題と `with('image')`（まとめ買いの考え方）

一覧では各ストーリーの「お題『〇〇』」を表示します。

**悪いやり方（N+1）**：

1. 「ストーリー10件ちょうだい」（1回）
2. 「1件目のお題は？」「2件目は？」…（10回）
3. 合計 **1 + 10 = 11回** 問い合わせ → 遅い

**良いやり方（`with()`）**：

```php
->with('image')
```

「ストーリーと一緒に、お題の情報も**まとめて**持ってきて」の指示。
→ 合計 **2回**で済む → 速い。

たとえ：
- N+1 ＝ 1個ずつスーパーに10往復
- `with()` ＝ メモして1回でまとめ買い

### 3.4 他人のストーリーは消せない（持ち主チェック）

```php
$story = auth()->user()->stories()->findOrFail($storyId);
$story->delete();
```

ポイントは**どこから探すか**。

- `auth()->user()->stories()` ＝ 「**自分の**ストーリーの中だけ」
- `->findOrFail($storyId)` ＝ その中からIDで探す。無ければエラー

探す範囲が最初から「自分のストーリーだけ」なので、他人のIDを渡しても見つからず、`delete()` に到達できません。
お気に入り解除（ステップ10）と同じ「**持ち主チェックを兼ねる探し方**」です。

危ない書き方（比較）：

```php
Story::findOrFail($storyId); // 全員の中から探す → 他人のも消せてしまう！
```

### 3.5 マイページでの削除は「その場にとどまる」

```php
Flux::toast('ストーリーを削除しました。', variant: 'success');
```

ステップ12の詳細ページでの削除とは動きが違います。

| 場所 | 削除後の動き |
| --- | --- |
| 詳細ページ（ステップ12） | お題ページへリダイレクト + `session()->flash()` |
| マイページ（今回） | マイページにとどまる + トースト表示 |

詳細ページでは「消したページには戻れない」ので別のページへ移動します。
マイページでは一覧からそのカードが消えるだけで、**ページ自体はそのまま**です。

### 3.6 空のときの出し分け

```blade
@if ($stories->isEmpty())
    {{-- 「まだ投稿がありません」の案内 --}}
@else
    {{-- 一覧 --}}
@endif
```

投稿が0件なら案内文、1件以上あれば一覧。ユーザーが迷わないための気配りです。
完成・散文の両方が表示されます（完成だけに絞っていません）。

### 3.7 お気に入り一覧へのリンク

```blade
<flux:button :href="route('bookmarks')" ...>
    お気に入り一覧
</flux:button>
```

マイページから、ステップ10で作ったお気に入り一覧へすぐ行けるようにしました。
「自分が書いた話」と「保存した話」は別の場所で管理します。

## 4. 理解度チェック問題（4択・解答つき）

まずは選択肢を見て、自分で答えを考えてみましょう。解答と中学生レベルの解説は各問のすぐ下にあります。

### Q1. `/mypage` を `auth` ミドルウェアのグループに入れている理由は？

- A. ページの表示を高速化するため
- B. 未ログインの人がアクセスしたらログインページへ送るため
- C. 管理者だけがアクセスできるようにするため
- D. ストーリーを自動で削除するため

**正解：B**

`middleware('auth')` は「**ログインしてる？**」を確認する関所です。マイページは自分のプロフィールと投稿を見るページなので、未ログインの人は関所で止められ、ログイン画面へ送られます。

引っかけ：A は表示速度とは無関係、C は `admin` ミドルウェアの話、D は削除とは関係ありません。

### Q2. `auth()->user()->stories()->latest()->get()` の意味は？

- A. すべてのユーザーのストーリーを新着順で取得する
- B. 今ログインしている人のストーリーを、新しい順に取得する
- C. 今ログインしている人のストーリーを、古い順に取得する
- D. 今ログインしている人がお気に入りしたストーリーを取得する

**正解：B**

- `auth()->user()` … 今ログインしている**自分**
- `->stories()` … その人が**書いた**ストーリーたち
- `->latest()` … **新しいものが先**
- `->get()` … 実際に取ってくる

引っかけ：A は全員分を取ってしまう危ない書き方、C は `oldest()` の話、D はお気に入り（`bookmarks()`）の話です。

### Q3. マイページの `deleteStory` で次のコードを使う理由は？

```php
$story = auth()->user()->stories()->findOrFail($storyId);
$story->delete();
```

- A. すべてのストーリーの中からIDで探すので、誰のストーリーでも消せる
- B. 「今のログインユーザーのストーリー」の中から探すので、他人のIDを渡しても見つからず消せない
- C. 削除すると必ずお題ページへリダイレクトするため
- D. お気に入りを解除するため

**正解：B**

探す場所が最初から「**自分のストーリーだけ**」に限定されています。他人のストーリーIDを渡しても、その中には見つからないので `findOrFail` がエラーを出し、`delete()` まで進みません。

引っかけ：A は `Story::findOrFail()` のような危ない書き方、C は詳細ページの削除の話（マイページではリダイレクトしない）、D はお気に入りの話です。

### Q4. `with('image')` を付ける狙いは？

- A. ストーリーをお題画像に分割して保存し直す
- B. 関連するお題画像をまとめて先に読み込み、無駄なクエリ（N+1）を防ぐ
- C. 完成したストーリーだけを表示する
- D. お題画像ファイルをサーバーから削除する

**正解：B**

一覧で「お題『〇〇』」を表示するとき、`with('image')` がないとストーリーごとにお題を別々に問い合わせて遅くなります（N+1問題）。まとめて読み込むことで、無駄なクエリを減らしています。

引っかけ：A・D はデータの変更・削除の話で無関係。C は完成だけ表示するなら別の書き方が必要です（マイページでは完成・散文の両方を表示しています）。

### Q5. マイページでストーリーを削除したあとの動きとして正しいのは？

- A. お題ページへリダイレクトし、`session()->flash()` で成功メッセージを渡す
- B. マイページにとどまり、トーストで「ストーリーを削除しました。」と表示する
- C. 削除したストーリーの詳細ページへ戻る
- D. 自動的にログアウトする

**正解：B**

マイページの `deleteStory()` は削除後に `Flux::toast(...)` を出すだけで、**ページはそのまま**です。一覧からそのカードが消えます。

ステップ12の詳細ページの削除とは動きが違います。詳細ページでは「消したページには戻れない」ので、お題ページへ `redirectRoute` します。

引っかけ：A は詳細ページ（`⚡show.blade.php`）の削除の動き、C は削除したストーリーの詳細ページはもう存在しないので404になる、D はログアウトとは無関係です。

### 5問のつながり（まとめ）

```
ログイン必須（Q1）→ 自分のストーリーだけ取得（Q2）
→ お題情報もまとめて読み込み（Q4）→ 自分の中からだけ削除（Q3）
→ 削除後はマイページにとどまる（Q5）
```

この5つがつながって「安全なマイページ」ができています。

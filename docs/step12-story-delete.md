このドキュメントは「文倉」開発ステップ12（ストーリー削除機能）の振り返りです。

## 0. このステップで作ったものを一言で

> 自分が書いたストーリーを、**本人だけが**削除できるようにした（確認ダイアログつき）。

これで「編集（update）」と「削除（delete）」が揃い、投稿の管理機能が一通り完成しました。

---

## 1. 全体の流れ

```
ストーリー詳細ページ …… 作者本人にだけ「削除」ボタンを表示
        │  クリック
        ▼
[確認ダイアログ] 「本当に削除しますか？」→ OK なら実行
        │
        ▼
deleteStory()（Livewire）
        │
        ├─ 1. 本人チェック（他人なら 403）
        ├─ 2. 戻り先のお題（image）を先に控える
        └─ 3. ストーリーを削除
        │
        ▼
お題ページへ戻る + 成功メッセージ
```

## 3. やさしい解説（中学生レベル）

### 3.1 削除も「本人だけ」の見張り番

```php
abort_unless($this->story->user_id === auth()->id(), 403);
```

編集のときと同じ考え方です。「このストーリーの作者IDが、今ログインしている自分と同じ？」を確認し、
違えば（＝他人なら）403で通せんぼ。**削除は取り返しがつかない**ので、権限チェックはとても大事です。

### 3.2 消す前に「戻り先」を控えておく

```php
$image = $this->story->image;

$this->story->delete();
```

ストーリーを消すと、その詳細ページは無くなってしまいます。
そこで、**消す前に**「どのお題に紐づいていたか（image）」を変数に控えておきます。
これがないと、削除後に「どこへ戻ればいいか」が分からなくなります。

覚え方：**消える前に、行き先のメモを取っておく**。

### 3.3 `delete()` は1件消す

```php
$this->story->delete();
```

- `update()`（ステップ11）… 既存の内容を**書き換える**
- `delete()`（今回）… 既存のデータを**消す**

対にして覚えると分かりやすいです。

### 3.4 消したあとは別ページへ戻す

```php
session()->flash('status', 'ストーリーを削除しました。');

$this->redirectRoute('images.show', $image, navigate: true);
```

詳細ページはもう無いので、3.2で控えた**お題ページ**へ戻します。
`session()->flash()` は「次のページに1回だけメッセージを渡す」しくみです。

### 3.5 確認ダイアログ（押し間違い防止）

```blade
<flux:button
    wire:click="deleteStory"
    wire:confirm="このストーリーを削除しますか？この操作は取り消せません。"
    icon="trash"
>削除</flux:button>
```

`wire:confirm` を付けると、ボタンを押した瞬間に「OK / キャンセル」の確認が出ます。
OK を押したときだけ `deleteStory` が動くので、うっかり削除を防げます。
（コメント削除でも使った、おなじみのしくみです。）

### 3.6 削除ボタンは本人にだけ

```blade
@if ($story->user_id === auth()->id())
    ...（編集・削除ボタン）...
@endif
```

作者本人のときだけボタンを表示。他人の画面には出ません。
（ボタンが無くても、`deleteStory()` の中の 3.1 のチェックで最終的に弾かれます。＝二重の守り）

## 4. 理解度チェック問題（4択・解答つき）

まずは選択肢を見て、自分で答えを考えてみましょう。解答と中学生レベルの解説は各問のすぐ下にあります。

### Q1. `abort_unless($this->story->user_id === auth()->id(), 403);` を書く理由は？

- A. 削除を速くするため
- B. 他人のストーリーを削除できないようにするため
- C. ログイン画面を表示するため
- D. コメントを一緒に消すため

**正解：B**

`abort_unless` は「**〜でなければ、止める（403で通せんぼ）**」という命令です。

- `$this->story->user_id` … このストーリーを書いた人のID
- `auth()->id()` … 今ログインしている自分のID
- `===` … 「同じ？」を確かめる

つまり「**書いた人＝今の自分**、じゃなければストップ」という意味。これがないと他人のストーリーまで消せてしまいます。削除は取り返しがつかないので、**見張り番**として必ず置きます。

引っかけ：A「速くする」は無関係、C の出すのは403（アクセス禁止）画面、D コメントは関係なし。

### Q2. `$this->story->delete();` の「前」に `$image = $this->story->image;` を書くのはなぜ？

- A. 紐づくお題画像も一緒に削除するため
- B. タイトルを変更するため
- C. 削除後の戻り先（お題ページ）を、ストーリーが消える前に控えておくため
- D. 意味はなく飾り

**正解：C**

ストーリーを消すと、その詳細ページも消えます。すると「削除できた。で、次はどの画面へ行く？」となります。そこで**消す前に**「このストーリーはどのお題（image）についていたか」をメモ（変数 `$image`）しておき、最後にそのお題ページへ戻します。

たとえ話：**家を取り壊す前に、次に行く場所の住所をメモしておく**イメージ。壊してからでは住所が分かりません。

引っかけの A が要注意。ここで消えるのは**ストーリーだけ**で、お題画像は消しません。むしろ「そこへ戻るため」に控えているのです。

### Q3. ステップ11の `update()` と、今回の `delete()` の違いは？

- A. update は内容を書き換える／delete はデータを消す
- B. どちらも新規作成する
- C. update は消す／delete は書き換える
- D. 違いはない

**正解：A**

- `update()` … すでにあるストーリーの**中身を書き直す**（＝ステップ11の編集）
- `delete()` … そのストーリー**そのものを消す**（＝今回）

たとえ話：`update()` は「ノートの文字を消しゴムで直して書き直す」、`delete()` は「ノートのページごと破って捨てる」。B・C は説明が逆や間違い、D は「違いがある」ので誤り。

### Q4. 削除ボタンにつけた `wire:confirm="..."` の役割は？

- A. 入力値を検証する
- B. 画面の色を変える
- C. ボタンを押したとき確認ダイアログを出し、OK のときだけ実行する
- D. ログアウトする

**正解：C**

`wire:confirm` を付けると、ボタンを押した瞬間に「**本当に削除しますか？ OK / キャンセル**」の小窓が出ます。OK を押したときだけ `deleteStory` が動き、キャンセルなら何も起きません。これで「**うっかり押しちゃった**」事故を防げます。

引っかけ：A の検証は `validate()` の仕事、B の色替えや D のログアウトは無関係。

### Q5. 削除後に `redirectRoute('images.show', $image)` でお題ページへ戻すのはなぜ？

- A. トップページが壊れているから
- B. 削除したストーリーの詳細ページは、もう存在しないから
- C. 管理者だけが見られるページだから
- D. ログインが必要だから

**正解：B**

`redirectRoute` は「**指定したページへ移動させる**」命令です。削除直後に元の詳細ページ（`stories.show`）へ戻そうとすると、そのストーリーはもう無いので「ページが見つかりません（404）」になります。だから Q2 で控えた `$image`（お題ページ）へ戻します。**「消したページには戻れないので、1つ手前のページへ返す」**という考え方です。

引っかけ：A・C・D はどれも理由になっていません。

### 5問のつながり（まとめ）

```
本人か確認（Q1）→ 戻り先をメモ（Q2）→ 消す delete（Q3）
→ 押し間違い防止の確認（Q4）→ 消えたページには戻れないので お題ページへ（Q5）
```

この5つがつながって「安全なストーリー削除」ができています。

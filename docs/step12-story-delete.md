# ステップ12 振り返り：ストーリー削除機能

このドキュメントは「文倉」開発ステップ12（ストーリー削除機能）の振り返りです。
ステップ11の「編集」と対になる機能で、**本人だけが削除できる**ように作りました。

## 0. このステップで作ったものを一言で

> 自分が書いたストーリーを、**本人だけが**削除できるようにした（確認ダイアログつき）。

これで「編集（update）」と「削除（delete）」が揃い、投稿の管理機能が一通り完成しました。

---

## 1. 全体の流れ

```
ストーリー詳細ページ …… 作者本人にだけ「削除」ボタンを表示
        │  クリック
        ▼
[確認ダイアログ] 「本当に削除しますか？」→ OK なら実行
        │
        ▼
deleteStory()（Livewire）
        │
        ├─ 1. 本人チェック（他人なら 403）
        ├─ 2. 戻り先のお題（image）を先に控える
        └─ 3. ストーリーを削除
        │
        ▼
お題ページへ戻る + 成功メッセージ
```

## 3. やさしい解説（中学生レベル）

### 3.1 削除も「本人だけ」の見張り番

```php
abort_unless($this->story->user_id === auth()->id(), 403);
```

編集のときと同じ考え方です。「このストーリーの作者IDが、今ログインしている自分と同じ？」を確認し、
違えば（＝他人なら）403で通せんぼ。**削除は取り返しがつかない**ので、権限チェックはとても大事です。

### 3.2 消す前に「戻り先」を控えておく

```php
$image = $this->story->image;

$this->story->delete();
```

ストーリーを消すと、その詳細ページは無くなってしまいます。
そこで、**消す前に**「どのお題に紐づいていたか（image）」を変数に控えておきます。
これがないと、削除後に「どこへ戻ればいいか」が分からなくなります。

覚え方：**消える前に、行き先のメモを取っておく**。

### 3.3 `delete()` は1件消す

```php
$this->story->delete();
```

- `update()`（ステップ11）… 既存の内容を**書き換える**
- `delete()`（今回）… 既存のデータを**消す**

対にして覚えると分かりやすいです。

### 3.4 消したあとは別ページへ戻す

```php
session()->flash('status', 'ストーリーを削除しました。');

$this->redirectRoute('images.show', $image, navigate: true);
```

詳細ページはもう無いので、3.2で控えた**お題ページ**へ戻します。
`session()->flash()` は「次のページに1回だけメッセージを渡す」しくみです。

### 3.5 確認ダイアログ（押し間違い防止）

```blade
<flux:button
    wire:click="deleteStory"
    wire:confirm="このストーリーを削除しますか？この操作は取り消せません。"
    icon="trash"
>削除</flux:button>
```

`wire:confirm` を付けると、ボタンを押した瞬間に「OK / キャンセル」の確認が出ます。
OK を押したときだけ `deleteStory` が動くので、うっかり削除を防げます。
（コメント削除でも使った、おなじみのしくみです。）

### 3.6 削除ボタンは本人にだけ

```blade
@if ($story->user_id === auth()->id())
    ...（編集・削除ボタン）...
@endif
```

作者本人のときだけボタンを表示。他人の画面には出ません。
（ボタンが無くても、`deleteStory()` の中の 3.1 のチェックで最終的に弾かれます。＝二重の守り）

## 4. 理解度チェック問題（解答つき）

**Q1.** `deleteStory()` の先頭で `abort_unless(本人か?, 403)` を書く理由は？
- **A. 他人のストーリーを削除できないようにするため**（正解）
- B. 削除を速くするため
- C. ログイン画面を出すため
- D. コメントを消すため

**Q2.** `$image = $this->story->delete();` の**前**に `$image = $this->story->image;` を書くのはなぜ？
- A. 画像を削除するため
- **B. 削除後の戻り先（お題ページ）を、消える前に控えておくため**（正解）
- C. タイトルを変更するため
- D. 意味はなく飾り

**Q3.** `update()` と `delete()` の違いは？
- **A. update は内容を書き換える／delete はデータを消す**（正解）
- B. どちらも新規作成する
- C. update は消す／delete は書き換える
- D. 違いはない

**Q4.** `wire:confirm="..."` の役割は？
- A. 入力値を検証する
- **B. ボタンを押したとき確認ダイアログを出し、OK のときだけ処理を実行する**（正解）
- C. 画面の色を変える
- D. ログアウトする

**Q5.** 削除後に `redirectRoute('images.show', $image)` へ戻すのはなぜ？
- A. トップページが壊れているから
- **B. 削除したストーリーの詳細ページはもう存在しないから**（正解）
- C. ログインが必要だから
- D. 管理者だけが見られるページだから

## 5. 動作確認の方法

```bash
composer run dev
```

1. ログイン（例: `test@example.com` / `password`）
2. 自分が書いたストーリーの詳細ページを開く →「削除」ボタンが出る
3. 「削除」を押す → 確認ダイアログで OK
4. お題ページへ戻り、そのストーリーが消えている
5. 他人のストーリーには削除ボタンが出ない

テスト:

```bash
php artisan test --filter=StoryDeleteTest
```

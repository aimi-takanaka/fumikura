# フリガナ機能をやさしく振り返る

文倉（fumikura）のストーリー本文に、**手動でフリガナを振れる機能**を入れたときの振り返りです。  
中学生やプログラミング初心者でも読めるように書いています。

この記事では、実装の要点と、学習中に出た質問への答えもまとめます。

---

## 1. 何ができるようになったか

作者は本文に、次のような記号でフリガナを書けます。

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `漢字《かんじ》` | 直前の漢字にフリガナ | `灯台《とうだい》` |
| `｜言葉《ことば》` | パイプで範囲を指定（ひらがな・カタカナにも使える） | `｜カタカナ《かたかな》` |

読む人の画面では、教科書のように「上に小さい読み、下に本体の文字」と表示されます。

---

## 2. 結論：やっていることはとてもシンプル

やっていることは、ざっくり3つだけです。

```text
1. 書く人は記号つきで本文を書く（そのまま保存）
2. 表示するとき、記号を見つけてフリガナ用HTMLに変換する
3. ブラウザがそのHTMLを見て、フリガナつきで見せる
```

たとえ話にするとこうです。

| 役割 | たとえ | このプロジェクトでの場所 |
| --- | --- | --- |
| 書き方の約束 | 「フリガナは《　》で書く」というルール | 投稿・編集画面のヒント文言 |
| 変換係 | 記号を見て、見やすい形に直す係 | `app/Support/Furigana.php` |
| 表示係 | 変換結果を画面に出す係 | `resources/views/components/story-body.blade.php` |
| 呼び出し | 「本文を出して」とお願いする場所 | `resources/views/pages/stories/⚡show.blade.php` |

データベースに新しい表を作ったわけではありません。  
本文（`body`）の中に、記号つきの文章を**そのまま文字として保存**しています。

---

## 3. 全体の流れ

```text
作者が本文を書く
例: 灯台《とうだい》の夜
        ↓
データベースにそのまま保存
        ↓
詳細ページを開く
        ↓
Furigana::toHtml() が変換
        ↓
<ruby>灯台<rt>とうだい</rt></ruby>の夜
        ↓
ブラウザがフリガナつきで表示
```

一覧（お題詳細・マイページなど）の短いプレビューでは、  
記号を外した読みやすい文章だけを見せます（`Furigana::toPlain()`）。

---

## 4. 代表的なコード

### 4-1. 変換係（いちばん大事）

`app/Support/Furigana.php` の `toHtml()` が中心です。

やっていること:

1. `漢字《かんじ》` や `｜言葉《ことば》` を探す
2. 見つからなければ、普通の文章を安全にして返す
3. 見つかったら、「普通の文」と「フリガナ部分」を交互に組み立てる
4. フリガナ部分だけ `<ruby>…</ruby>` にする

いちばん大事な1行はこれです。

```php
$html .= '<ruby>'.e($base).'<rp>（</rp><rt>'.e($reading).'</rt><rp>）</rp></ruby>';
```

| 部品 | 意味 |
| --- | --- |
| `ruby` | フリガナつき文字の箱 |
| `rt` | 上に乗る読み |
| `rp` | 古い環境向けの（　） |
| `e()` | 危険な文字を無害化する（エスケープ） |

### 4-2. 表示部品

`resources/views/components/story-body.blade.php`

```blade
{!! \App\Support\Furigana::toHtml($body) !!}
```

- `{!! !!}` … HTMLとして表示する
- 普通の `{{ }}` だと、`<ruby>` が文字のまま見えてしまう

### 4-3. 詳細ページからの呼び出し

`resources/views/pages/stories/⚡show.blade.php`

```blade
<x-story-body :body="$story->body" class="leading-relaxed" />
```

「この本文を、フリガナ対応の部品で出して」という意味です。

## 6. 学習中の質問と答え

### Q1. いろんなファイルを変えたけど、何をしたの？

**A.**  
書く人は記号でフリガナを指定し、読む人には普通のフリガナに見える仕組みを足しました。  
保存は今までどおり本文の文字のままです。表示のときにだけ変換します。

---

### Q2. `<ruby>` 付きHTMLは、ひとまとめに認識するため？

**A.**  
近いです。もう少し正確に言うと、`<ruby>` は**ブラウザがもともと知っているフリガナ用のHTMLの書き方**です。

例:

```html
<ruby>灯台<rt>とうだい</rt></ruby>
```

- `<ruby>…</ruby>` … 「この範囲はフリガナつき」と伝える箱
- `灯台` … 本体
- `<rt>とうだい</rt>` … 上に載せる読み

文倉が発明した独自ルールではなく、HTMLの標準機能です。  
「ひとまとめの箱にして扱う」という理解で大丈夫です。

---

### Q3. `toHtml()` は一行ずつ何をしている？

超短まとめ:

1. フリガナ記号を探すルールを用意する
2. なければ安全にしてそのまま返す
3. あれば「普通の文」と「フリガナ部分」を交互に組み立てる
4. フリガナ部分だけ `<ruby>` にする
5. 全部まとめて返す

カーソル（`$cursor`）は、「ここまでは処理済み」というしおりみたいなものです。

---

### Q4. この書き方はどういう意味？

```php
$base = ($match[1][0] ?? '') !== '' ? $match[1][0] : ($match[2][0] ?? '');
```

部品ごとの意味:

| 記号 | 意味 |
| --- | --- |
| `?? ''` | 左がない（未設定）なら、空文字 `''` を使う |
| `!== ''` | 空文字ではない |
| `A ? B : C` | Aが正しければB、そうでなければC |

日本語にすると:

1. まず `[1]`（パイプ付きの言葉）を見る
2. それが空じゃなければ、それを本体にする
3. 空なら `[2]`（漢字）を本体にする

なぜなら、次のどちらか一方しか入らないからです。

- `｜言葉《ことば》` → `[1]` に入る
- `漢字《かんじ》` → `[2]` に入る

---

## 7. なぜ「手動」にしたか

フリガナには、だいたい2つのやり方があります。

| やり方 | 内容 | 向いていること |
| --- | --- | --- |
| 手動（今回） | 作者が `漢字《かんじ》` と書く | 作者の意図どおりに振れる。実装が分かりやすい |
| AI自動 | コンピュータが読みを付ける | 楽だが、間違い・確認UI・コストが増える |

今回は「作者が自分で振りたい」という方針で、手動（青空文庫風）にしました。

---

## 8. 安全のためにやっていること

本文をHTMLとして出すので、悪い文字がそのまま動くと危険です。  
そのため、次のようにしています。

- 普通の文章は `e()` でエスケープする
- フリガナの本体・読みも `e()` する
- 自分たちが作った `<ruby>` タグだけをHTMLとして出す

「全部を危険なまま出す」のではなく、  
「安全にした文字 ＋ 自分たちで作ったフリガナタグ」だけを出す、という考え方です。

| テスト | 確かめていること |
| --- | --- |
| `tests/Unit/FuriganaTest.php` | 記号がルビになる／パイプが使える／HTMLが無害化される／記号を外せる |
| `tests/Feature/StoryFuriganaTest.php` | 詳細ページに `<ruby>` が出る／投稿画面に書き方ヒントがある |

テストを走らせる例:

```bash
php artisan test --compact tests/Unit/FuriganaTest.php tests/Feature/StoryFuriganaTest.php
```

## 10. 覚えたい一言

> **保存は記号つきのただの文字。見せるときだけ `<ruby>` に変える。**

これが分かれば、この機能の半分は理解できています。

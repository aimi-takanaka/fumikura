## 3. なぜそう作ったのか（設計の意図）

### 3.1 なぜ「ミドルウェア」で守るのか

「管理者だけ」というチェックを、画面のあちこちに書くと漏れやすくなります。
**門番（ミドルウェア）にまとめておけば、ルートに付けるだけ**で確実に守れ、今後の管理者ページにも再利用できます。

```php
abort_unless($request->user()?->is_admin, 403);
```

`?->` は「ユーザーがいれば is_admin を見る、いなければ null」という安全な書き方（null でも落ちない）。

### 3.2 なぜ「二重の門番」なのか

```php
Route::middleware(['auth', 'admin'])->group(...)
```

- `auth` … 未ログインは弾く（→ ログイン画面へ）
- `admin` … ログイン済みでも管理者以外は弾く（→ 403）

役割を分けることで、それぞれのミドルウェアが単純になり、使い回しやすくなります。

### 3.3 画像は「DBに入れない」

画像そのものはファイルとして `storage` に保存し、DBには**その保存場所（パス）だけ**を記録します。

- DBが軽くなり、表示も速い（一般的なベストプラクティス）
- `images.file_path` に `images/xxxx.jpg` のような文字列が入る

### 3.4 storage:link の役割

Laravel は画像を `storage/app/public` に保存しますが、そのままではブラウザから見えません。
`php artisan storage:link` で `public/storage` → `storage/app/public` の**近道（シンボリックリンク）**を作り、URLでアクセスできるようにします。

## 4. つまずき／セキュリティのポイント

### 4.1 バリデーションはセキュリティでもある

```php
#[Validate('required|image|max:5120')]
public $photo = null;
```

- `image` … 画像以外（PDFや実行ファイル等）を弾く
- `max:5120` … 5MB を超える巨大ファイルを弾く

**ファイルアップロードは攻撃の入口になりやすい**ため、種類とサイズの検証は必須です。

### 4.2 プレビューは「画像のときだけ」

非画像ファイルを選んだ状態で `->temporaryUrl()` を呼ぶとエラーになります。
そのため、プレビュー表示は次のようにガードしています。

```blade
@if ($photo && $photo->isPreviewable())
```

### 4.3 ファイルアップロードのプロパティは「型なし」が無難

Livewire のファイル用プロパティは `public $photo = null;`（型指定なし）にしています。
厳密な型を付けると、アップロード途中の状態で型エラーになることがあるためです。

### 4.4 テスト環境の注意（GD拡張）

この環境の PHP には画像生成用の **GD拡張が入っていない**ため、テストで `UploadedFile::fake()->image()` が使えません。
代わりに、MIMEタイプを指定した疑似ファイルで検証しました（本番動作には影響なし）。

```php
UploadedFile::fake()->create('sunset.jpg', 100, 'image/jpeg');
```

## 5. コード読解トレーニング（コードを見て言語化する）

「知識として分かる」と「コードを見て何をしているか説明できる」は別のスキルです。
ここでは実際のコードを読んで、**自分の言葉で説明する練習**をします。各コードの下に「読み上げ方（模範解答）」を用意しました。

### 問1

```php
abort_unless($request->user()?->is_admin, 403);
```

**読み上げ方**：「もしログインユーザーが管理者でなければ、403（アクセス拒否）で処理を止める」

- `abort_unless(条件, 403)` = 「条件が false なら 403 で中断」
- `$request->user()?->is_admin` = 「リクエストした人の is_admin を見る（いなければ null）」
- `?->` = 「相手が null でも落ちないようにする安全装置」

### 問2

```php
$path = $this->photo->store('images', 'public');
```

**読み上げ方**：「選ばれた画像を public ディスクの images フォルダに保存して、その保存先パスを $path に受け取る」

- `store('images', 'public')` = 「public という保存場所の images フォルダにしまう」
- 戻り値（保存パス）を `$path` に入れて、あとでDBに記録する

### 問3

```php
Image::create([
    'title' => $this->title,
    'file_path' => $path,
    'user_id' => auth()->id(),
]);
```

**読み上げ方**：「images テーブルに1行追加する。タイトル・画像の保存パス・投稿した管理者のID を記録する」

- `Image::create([...])` = 「Image（=images テーブル）に新しいレコードを作る」
- `auth()->id()` = 「今ログインしている人のID」

### 問4

```php
session()->flash('status', 'お題画像を投稿しました。');
$this->redirectRoute('home', navigate: true);
```

**読み上げ方**：「成功メッセージを“次の1回だけ”持たせて、トップページに移動する」

- `flash` = 「次のページ表示のときだけ残るメッセージ」（レイアウトがこれを拾って緑の通知を出す）
- `redirectRoute('home', navigate: true)` = 「home へ移動（`navigate: true` で画面をスムーズに切り替え）」

### 問5

```blade
@auth
    @if (auth()->user()->is_admin)
        <flux:button :href="route('admin.images.create')" ...>お題を投稿</flux:button>
    @endif
@endauth
```

**読み上げ方**：「ログイン済み かつ 管理者のときだけ、『お題を投稿』ボタンを表示する」

- `@auth` = 「ログインしている人だけ、この中を表示」
- `@if (...is_admin)` = 「さらに管理者に限定」→ 二重の絞り込み

### 言語化のコツ（どのコードでも使える）

1. **左から右へ、主語・述語に変換**：`$this->photo->store(...)` →「この写真を、保存する」
2. **カッコの中身は「何を・どこに」**：`store('images', 'public')` →「imagesフォルダに、publicで」
3. **戻り値は「〜を受け取る」**：`$path = ...` →「結果を path に受け取る」
4. **記号は役割で覚える**：`?->`=安全に読む、`=>`=キーと値のペア、`::`=そのクラスの機能

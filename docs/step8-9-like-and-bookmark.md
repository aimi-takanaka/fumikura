# ステップ8・9 振り返り：いいね機能 & お気に入り機能

このドキュメントは「文倉」開発ステップ8（いいね）とステップ9（お気に入り／ブックマーク）の振り返りです。
2つはほぼ同じ作りなので、**「1つの型を別の機能に応用する」**という視点でまとめます。
やさしい解説（中学生レベル）と、理解度チェック問題（解答つき）も収録しました。

---

## 0. この2ステップで作ったものを一言で

> ストーリー詳細ページで、ログインユーザーが
> - **いいね**（♥）を付けたり外したりできる（ステップ8）
> - **お気に入り**（保存）を付けたり外したりできる（ステップ9）

どちらも同じボタンで「つける／外す」を切り替える**トグル**方式です。

---

## 1. 「同じ4部品」でできている

いいねもお気に入りも、次の4つの部品の組み合わせです。名前が `likes` か `bookmarks` に変わるだけ。

| 部品 | やること | コード |
| --- | --- | --- |
| ① 見張り番 | ログインしてない人は止める | `abort_unless(auth()->check(), 403);` |
| ② 自分の分を探す | 自分が付けた1件を探す | `->where('user_id', auth()->id())->first()` |
| ③ スイッチ | あれば消す・なければ作る | `if (...) delete() else create()` |
| ④ 状態を見せる | 付けたかどうかで色・文字を変える | `$isLiked ? 'primary' : 'ghost'` |

---

## 2. やさしい解説（中学生レベル）

### ① 見張り番

```php
abort_unless(auth()->check(), 403);
```

入口の見張り番です。「ログインしてる？」→ してなかったら**通せんぼ**（止める）。

### ② 自分の分を探す

```php
$existingLike = $this->story->likes()
    ->where('user_id', auth()->id())
    ->first();
```

「このお話に、**自分が**つけたいいねが1個あるか探す」。あれば見つかるし、なければ「空っぽ」。

### ③ スイッチ

```php
if ($existingLike) {
    $existingLike->delete();          // もうあるなら消す
} else {
    $this->story->likes()->create([   // まだ無いなら付ける
        'user_id' => auth()->id(),
    ]);
}
```

電気のスイッチと同じ。同じボタンで「つける」も「消す」もできます（＝トグル）。

### ④ 状態を見せる

```blade
<flux:button :variant="$isLiked ? 'primary' : 'ghost'" icon="heart">
    {{ $likesCount }}
</flux:button>
```

`? :` は「**もし〜なら A、ちがうなら B**」。
付けてたら色つき（primary）、まだなら控えめ（ghost）。SNSのハートが押すと赤くなるのと同じ発想です。

## 3. いいねとお気に入りの違いは「名前」だけ

同じ処理を、テーブル名（リレーション名）を変えて2回書いただけです。

```php
// いいね
$this->story->likes()->where('user_id', auth()->id())->first();
$this->story->likes()->create(['user_id' => auth()->id()]);

// お気に入り
$this->story->bookmarks()->where('user_id', auth()->id())->first();
$this->story->bookmarks()->create(['user_id' => auth()->id()]);
```

`likes` ↔ `bookmarks` に置き換わっているだけ。だから、いいねが読めればお気に入りも読める、というわけです。

---

## 4. 二重防止のしくみ（大事）

同じ人が同じストーリーに2回いいね／保存できないように、**2段構え**で守っています。

1. **データベース側**：`likes` / `bookmarks` テーブルに `unique(['story_id', 'user_id'])` 制約（同じ組み合わせは1行だけ）
2. **プログラム側**：③のスイッチで「あれば消す・なければ作る」なので、そもそも2件目を作らない

テストでも「3回押しても常に1件」を確認済みです。

## 6. 理解度チェック問題（解答つき）

### ステップ8：いいね機能

**Q1.** `abort_unless(auth()->check(), 403);` の役割は？
- A. いいねの合計数が0なら止める
- **B. ログインしていない場合は403で止める**（正解）
- C. 管理者以外を403で止める
- D. すでにいいね済みなら止める

**Q2.** `if ($existingLike) delete else create` の分岐は何をしている？
- A. いいねが存在しても必ず作り直す
- B. いいねを2件同時に作成する
- **C. すでに自分のいいねがあれば取り消し、なければ付ける（トグル）**（正解）
- D. 他人のIDで作成する

**Q3.** `likes()->where('user_id', auth()->id())->first()` の意味は？
- **A. このストーリーの、今のログインユーザーによるいいねを1件だけ探す**（正解）
- B. すべてのユーザーのいいねを取得する
- C. すべてのストーリーのいいねを合計する
- D. 今のユーザーのいいねをすべて削除する

**Q4.** `isLiked` は何を表す？
- A. 誰か1人でもいいねしているか
- **B. ログイン中で、かつ自分がいいね済みかどうか**（正解）
- C. いいねの合計数が偶数か
- D. 自分が管理者か

**Q5.** `:variant="$isLiked ? 'primary' : 'ghost'"` としている理由は？
- **A. いいね済みかどうかで見た目（色）を変え、状態が分かるようにするため**（正解）
- B. ボタンを押せないようにするため
- C. いいね数を2倍で表示するため
- D. ログインページへ移動させるため

### ステップ9：お気に入り機能

**Q1.** `toggleBookmark()` 先頭の `abort_unless(auth()->check(), 403);` の役割は？
- A. 保存の合計数が0なら止める
- B. すでに保存済みなら止める
- **C. ログインしていない場合は403で止める**（正解）
- D. 管理者以外を403で止める

**Q2.** `if ($existingBookmark) delete else create` は何をしている？
- **A. すでに保存していれば解除し、していなければ保存する（トグル）**（正解）
- B. 保存を必ず2件作る
- C. 保存があっても必ず作り直す
- D. 他人のIDで保存する

**Q3.** `bookmarks()->where('user_id', auth()->id())->first()` の意味は？
- A. このストーリーの全員分の保存を取得する
- **B. このストーリーに対する「自分の」保存を1件だけ探す**（正解）
- C. 全ストーリーの保存数を合計する
- D. 自分の保存をすべて削除する

**Q4.** `isBookmarked` は何を表す？
- A. 保存の合計が偶数か
- B. 誰か1人でも保存しているか
- **C. ログイン中で、かつ自分がこのストーリーを保存済みか**（正解）
- D. 自分が管理者か

**Q5.** `{{ $isBookmarked ? '保存済み' : '保存' }}` としている理由は？
- **A. 今保存しているかどうかで、ボタンの文字（と色）を切り替えて状態を見せるため**（正解）
- B. ボタンを押せなくするため
- C. 保存数を2倍で表示するため
- D. ログインページに移動させるため

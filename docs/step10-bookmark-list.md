## 0. このステップで作ったものを一言で

> ログインユーザーが、**自分が保存（お気に入り）したストーリーを一覧で読み返せる**ページを作った。

ストーリー詳細ページの「保存」ボタンと対になる機能です。保存したものが後からまとめて見られます。

## 1. 全体の流れ

```
ヘッダーの「お気に入り」ボタン（ログイン時のみ表示）
        │  wire:navigate
        ▼
[門番] auth ミドルウェア …… 未ログインはログイン画面へ
        │
        ▼
/bookmarks（Livewire）
        │  with()
        ▼
自分の保存を新しい順に取得（関連するストーリー・作者・お題画像もまとめて）
        │
        ▼
一覧表示（各カードは詳細ページへリンク / 「保存を外す」ボタンつき）
```

## 3. やさしい解説（中学生レベル）

### 3.1 「ログイン必須」の作り方

```php
Route::middleware('auth')->group(function () {
    Route::livewire('/bookmarks', 'pages::bookmarks')->name('bookmarks');
});
```

- `middleware`（ミドルウェア）＝ ページを表示する**前に通る関所**
- `'auth'` ＝ 「ログインしてる？」を確認する関所
- `->group(...)` ＝ 「この中のページ全部に、その関所を付ける」

つまり「**この中のページはログイン必須**」の合図。未ログインの人は関所で止められ、ログイン画面へ送られます。

### 3.2 `latest()` は「新しい順」

```php
auth()->user()->bookmarks()->latest()->get();
```

- `auth()->user()` ＝ 今ログインしている本人
- `->bookmarks()` ＝ その人の保存たち
- `->latest()` ＝ **新しいものが先**（最近保存したものが上）
- `->get()` ＝ 実際に取ってくる

※古い順にしたいときは `oldest()`。

### 3.3 N+1問題と `with()`（まとめ買いの考え方）

まず「**クエリ**」＝ データベースへの**問い合わせ（質問）**のこと。

保存が10件あって、それぞれの作者名を出したいとき——

**悪いやり方（N+1）**：

1. 「保存10件ちょうだい」（1回）
2. 「1件目の作者は？」「2件目は？」…（10回）
3. 合計 **1 + 10 = 11回** 問い合わせ → 遅い

**良いやり方（`with()`）**：

```php
->with(['story.user', 'story.image'])
```

「保存と一緒に、関連するストーリー・作者・お題画像も**まとめて**持ってきて」の指示。
→ 合計 **3回**で済む → 速い。

たとえ：
- N+1 ＝ 1個ずつスーパーに10往復
- `with()` ＝ メモして1回でまとめ買い

これが「無駄なクエリ（N+1）を防ぐ」という意味です。

### 3.4 他人の保存を消せない理由（持ち主チェック）

```php
$bookmark = auth()->user()->bookmarks()->findOrFail($bookmarkId);
$bookmark->delete();
```

ポイントは**どこから探すか**。

- `auth()->user()->bookmarks()` ＝ 「**自分の**保存の中だけ」
- `->findOrFail($bookmarkId)` ＝ その中からIDで探す。無ければエラー（見つからない＝404）

探す範囲が最初から「自分の保存だけ」なので、他人のIDを渡しても見つからず、`delete()` に到達できません。

危ない書き方（比較）：

```php
Bookmark::findOrFail($bookmarkId); // 全員の中から探す → 他人のも消せてしまう！
```

`auth()->user()->bookmarks()` から探すことで、**持ち主チェックを兼ねている**のがコツです。

### 3.5 空のときの出し分け

```blade
@if ($bookmarks->isEmpty())
    {{-- 「まだお気に入りがありません」の案内 --}}
@else
    {{-- 一覧 --}}
@endif
```

保存が0件なら案内文、1件以上あれば一覧。ユーザーが迷わないための気配りです。

## 4. 理解度チェック問題（解答つき）

**Q1.** `/bookmarks` を `auth` ミドルウェアのグループに入れている理由は？
- **A. 未ログインの人がアクセスしたらログインページへ送るため**（正解）
- B. 管理者だけがアクセスできるようにするため
- C. ページの表示を高速化するため
- D. 保存を自動で削除するため

**Q2.** `auth()->user()->bookmarks()->latest()->get()` の意味は？
- A. すべてのユーザーの保存を新着順で取得する
- **B. 今ログインしている人の保存を、新しい順に取得する**（正解）
- C. 今ログインしている人の保存を、古い順に取得する
- D. 保存を1件だけ取得する

**Q3.** `with(['story.user', 'story.image'])` を付ける狙いは？
- A. 保存を story・user・image に分割して保存し直す
- **B. 関連するストーリー・作者・お題画像をまとめて先に読み込み、無駄なクエリ（N+1）を防ぐ**（正解）
- C. story と user と image を削除する
- D. 並び順をランダムにする

**Q4.** 次のコードが「他人の保存は消せない」ようにできているのはなぜ？
```php
$bookmark = auth()->user()->bookmarks()->findOrFail($bookmarkId);
$bookmark->delete();
```
- A. すべての保存の中からIDで探すので、誰の保存でも消せる
- **B. 「今のログインユーザーの保存」の中から探すので、他人のIDを渡しても見つからず消せない**（正解）
- C. 管理者のときだけ消せる
- D. 保存が2件以上あるときだけ消せる

**Q5.** `@if ($bookmarks->isEmpty()) ... @else ... @endif` は何をしている？
- **A. 保存が0件なら案内文を、1件以上あれば一覧を表示する**（正解）
- B. 保存が0件でも必ず一覧を表示する
- C. ログインしていない人だけに一覧を表示する
- D. 保存を新しく作成する

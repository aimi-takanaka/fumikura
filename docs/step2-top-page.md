## 0. このステップで作ったものを一言で

> URL `/` にアクセスすると、**お題画像の一覧が並ぶトップページ**が表示されるようにした。

ステップ1で作った土台（モデル・リレーション）の上に、初めて「目に見える画面」を1枚建てた段階です。

---

## 1. 全体の流れ（3ファイルの連携）

```
ブラウザで / にアクセス
        │
        ▼
routes/web.php  ……「/ は pages::home を表示」と案内
        │
        ▼
pages/⚡home.blade.php  …… 中身（画像をDBから取得＋カード表示）
        │  #[Layout('layouts.public')] で外枠を指定
        ▼
layouts/public.blade.php  …… 外枠（ヘッダー付きの共通レイアウト）
        │
        ▼
完成したHTMLがブラウザに返る
```

ポイントは **「中身」と「外枠」を別ファイルに分ける** という設計です。
これにより、ヘッダーを毎ページ書き直さずに済みます。

## 3. なぜそう書いたのか（設計の意図）

### 3.1 なぜフルページ Livewire コンポーネントにしたのか

トップページは今後「絞り込み」「並べ替え」などの動きを足す可能性があります。
最初から Livewire の部品にしておけば、**あとで JavaScript を書かずに動きを追加**できます。

### 3.2 データ取得の意図（N+1 を避ける）

```php
Image::query()
    ->with('user')                       // 投稿者をまとめて取得（N+1防止）
    ->withCount([
        'stories as completed_stories_count'
            => fn ($query) => $query->complete(),   // 完成ストーリーだけ数える
    ])
    ->latest()                           // 新しい順
    ->get();
```

- `with('user')` … 各カードで投稿者名を出すため。これが無いと画像の数だけ追加のDB問い合わせが発生します（＝N+1問題）。
- `withCount(...)` … ストーリー本文まで取ると重いので、**「件数」だけ**を効率的に取得。
- `$query->complete()` … ステップ1で定義したスコープを再利用。**土台が効いている好例**です。

### 3.3 なぜ「完成」だけ数えるのか

要件では、下書き（散文・アイデア）はログインユーザーだけが見られます。
トップページは全員に見えるので、公開してよい **完成ストーリーの件数** を表示しています。

### 3.4 ログイン状態での出し分け

```blade
@auth
    {{-- ログイン済み：ダッシュボード + 名前 --}}
@else
    {{-- 未ログイン：ログイン + 新規登録 --}}
@endauth
```

要件「トップページは全員が閲覧可」を満たしつつ、会員には導線を出しています。

## 4. つまずきポイント（重要）

### 4.1 Livewire ページは「外枠」を明示する

フルページ Livewire コンポーネントの冒頭には、必ずどの外枠を使うか書きます。

```php
new #[Layout('layouts.public')] #[Title('お題一覧')] class extends Component
```

**これが消えると、Livewire は既定の外枠（＝ログイン後専用のサイドバー枠）を勝手に使います。**
その結果、未ログインだと「名前が null」でエラー（`sidebar.blade.php:33`）になりました。

> 教訓：Livewire のページを作ったら、まず `#[Layout(...)]` を確認する。

### 4.2 ページの中身は「1つの要素」で囲む

Livewire コンポーネントの HTML は、必ず1個の親要素（`<div>` など）で囲みます。
複数の要素をトップレベルに並べると "Multiple root elements" エラーになります。

### 4.3 画面が真っ白／崩れるとき

Vite のビルド成果物が無いと `@vite` がエラーになります。次のどれかで解決します。

```bash
composer run dev   # 開発中（自動ビルド）
# または
npm run build      # 本番用にビルド
```

## 7. 現状の制限と次のステップ

いまの制限:

- カードのサムネイルは**仮の模様**（本物の画像はまだ未アップロード）
- カードを押しても**まだ遷移しない**（詳細ページが未作成）

次のステップ候補:

- **管理者の画像アップロード機能** … 本物のお題画像を登録できるようにする
- **画像詳細ページ** … カードから、その画像のストーリー一覧へ遷移

どちらも、ステップ1の土台とステップ2の画面をそのまま発展させて作ります。

# ステップ11 振り返り：ストーリー編集機能

このドキュメントは「文倉」開発ステップ11（ストーリー編集機能）の振り返りです。
要件「投稿後もステータス変更可能」を満たす機能で、**本人だけが編集できる**ように作りました。
やさしい解説（中学生レベル）と、理解度チェック問題（解答つき）を収録します。

---

## 0. このステップで作ったものを一言で

> 自分が書いたストーリーを、**本人だけが**あとから編集できるようにした（タイトル・本文・ステータスの変更）。

これで「下書き（散文・アイデア）→ 完成」への切り替えなど、投稿後の修正ができるようになりました。

---

## 1. 全体の流れ

```
ストーリー詳細ページ …… 作者本人にだけ「編集」ボタンを表示
        │  wire:navigate
        ▼
[門番] auth ミドルウェア（ログイン必須）
        │
        ▼
/stories/{story}/edit（Livewire）
        │  mount()
        ├─ 本人以外は 403
        └─ フォームに今の内容を初期表示
        │  update()
        ▼
1. 本人チェック（再確認）
2. バリデーション
3. 今のストーリーを上書き保存
        │
        ▼
詳細ページへ戻る + 成功メッセージ
```

## 3. やさしい解説（中学生レベル）

### 3.1 本人だけが入れる「見張り番」

```php
abort_unless($story->user_id === auth()->id(), 403);
```

「このストーリーの作者IDが、今ログインしている自分のIDと同じ？」を確認。
違えば（＝他人なら）403で通せんぼ。編集画面すら開けません。

### 3.2 フォームに「今の内容」を映しておく（初期表示）

```php
$this->title = $story->title;
$this->body = $story->body;
$this->status = $story->status->value;
```

編集画面を開いたとき、入力欄が空っぽだと最初から書き直しになってしまいます。
そこで、**画面の入力欄に“今のストーリーの内容”を先に入れておく**のがこの3行です。

矢印は「**右（保存済みの中身）を、左（画面の入力欄）に入れる**」向き。
だから編集画面には、すでにタイトルも本文も表示されていて、そこを直すだけで済みます。

覚え方：`$this->○○ = $story->○○;` は「画面に、今の中身を映しておく」。

### 3.3 ステータスだけ `->value` が付く理由（Enum → 文字）

```php
$this->status = $story->status->value;
```

前提が2つあります。

- **① ステータスは Enum（列挙型）という特別な型**
  `$story->status` は、ただの文字ではなく `StoryStatus::Complete` / `StoryStatus::Draft` という専用の型の値（ステップ1で作成）。
- **② ラジオボタンは「文字」で判断する**
  画面のラジオは `value="complete"` / `value="draft"` という**ただの文字**で選択を判断する。

この型の違いを埋めるのが `->value`：

- `$story->status` → `StoryStatus::Complete`（Enumの値）
- `$story->status->value` → `'complete'`（中の**文字**を取り出す）

これで「Enum → 文字」に変換され、ラジオボタンと正しくつながって、今のステータスに最初からチェックが入ります。

たとえ：Enumが「ラベル付きの箱」なら、`->value` は「箱を開けて中身（文字）を取り出す」動作。

### 3.4 上書き保存

```php
$validated = $this->validate([...]);
$this->story->update($validated);
```

- `validate()` … 検証を通った値だけを受け取る
- `update()` … **今のストーリー**の内容をその値で上書き（新規作成ではない）

`create()`（新しく作る）との違いに注目。編集は既存のものを**書き換える**ので `update()` です。

### 3.5 編集ボタンは本人にだけ

```blade
@if ($story->user_id === auth()->id())
    <flux:button :href="route('stories.edit', $story)" ...>編集</flux:button>
@endif
```

作者本人のときだけボタンを表示。他人の画面には出ません（そもそも直接URLを開いても3.1で弾かれます）。

## 4. 理解度チェック問題（解答つき）

**Q1.** `abort_unless($story->user_id === auth()->id(), 403);` は何をしている？
- **A. 作者が今のログインユーザーでなければ403で編集画面を開かせない**（正解）
- B. 作者が今のログインユーザーなら403で止める
- C. 管理者以外はすべて403で止める
- D. ステータスが下書きなら403で止める

**Q2.** `$this->title = $story->title;` などの3行の役割は？
- A. ストーリーを新しく作り直す
- **B. フォームの各項目に、いまのストーリーの内容を初期表示として入れる**（正解）
- C. ストーリーの内容をすべて空にする
- D. 入力値を検証してエラーを出す

**Q3.** ステータスだけ `$story->status->value` と `->value` を付ける理由は？
- **A. ステータスは Enum なので、ラジオで扱える文字列（'complete' / 'draft'）を取り出すため**（正解）
- B. ステータスを2倍の長さにするため
- C. ステータスを削除するため
- D. ステータスを数値の0に変換するため

**Q4.** `$this->story->update($validated);` の意味は？
- A. 新しいストーリーをもう1件作成する
- **B. 検証を通った値で、今のストーリーの内容を上書き保存する**（正解）
- C. ストーリーを削除してから作り直す
- D. 検証せずにそのまま保存する

**Q5.** `@if ($story->user_id === auth()->id())` で編集ボタンを囲う意味は？
- A. ログインしている全員に見せる
- **B. このストーリーの作者本人にだけ編集ボタンを見せる**（正解）
- C. 管理者にだけ見せる
- D. 誰にも見せない

## 5. 動作確認の方法

```bash
composer run dev
```

1. ログイン（例: `test@example.com` / `password`）
2. 自分が書いたストーリーの詳細ページを開く →「編集」ボタンが出る
3. タイトル・本文・ステータスを直して「更新する」
4. 詳細ページに戻り、変更が反映される（下書き→完成の切り替えもできる）
5. 他人のストーリーの編集URL（`/stories/{id}/edit`）を直接開くと 403 になる

テスト:

```bash
php artisan test --filter=StoryEditTest
```

# ステップ15 振り返り：ページネーション（マイページ・お題一覧）

このドキュメントは「文倉」開発ステップ15（ページネーション機能）の振り返りです。
マイページとお題一覧に、**投稿が多いときに10件ずつページ分けして表示する**機能を追加しました。
やさしい解説（中学生レベル）と、理解度チェック問題（解答つき）を収録します。

---

## 0. このステップで作ったものを一言で

> 一覧が長くなっても見やすいように、**10件ずつに分けて表示し、ページ送りで次のページを見られる**ようにした。

マイページ（自分の投稿）とお題一覧（トップページ）の両方に、同じ仕組みでページネーションを付けました。

---

## 1. 全体の流れ

```
一覧ページ（マイページ / お題一覧）
        │
        ├─ WithPagination トレイト … Livewire にページ送り機能を付ける
        │
        ├─ paginate(10) … 10件ずつデータを取る（get() ではなく）
        │
        ├─ 一覧を表示（@foreach）
        │
        └─ hasPages() が true なら … flux:pagination でページ送りボタンを表示
                │
                ├─ 次へ / 前へ / ページ番号クリック
                └─ マイページだけ：検索・絞り込み変更時に resetPage() で1ページ目へ
```

## 3. やさしい解説（中学生レベル）

### 3.1 なぜページ分けが必要？

投稿やお題が100件あるとき、**全部一度に表示**すると——

- 画面がとても長くなる
- データベースへの問い合わせも重くなる
- スクロールが大変になる

そこで「**ノートのページを分ける**」ように、10件ずつに分けて表示します。

### 3.2 `WithPagination` … ページ送り機能のスイッチ

```php
use Livewire\WithPagination;

new class extends Component {
    use WithPagination;
```

Livewire に「次のページ」「前のページ」「2ページ目へ」といった**ページ送り機能**を付けるトレイトです。

これがないと `nextPage()` や `flux:pagination` のボタンが動きません。

### 3.3 `get()` と `paginate(10)` の違い

**変更前（全部取る）:**

```php
->latest()->get();
```

**変更後（10件ずつ取る）:**

```php
private const PER_PAGE = 10;

->latest()->paginate(self::PER_PAGE);
```

| メソッド | 意味 |
| --- | --- |
| `get()` | 条件に合うデータを**全部**取る |
| `paginate(10)` | **10件ずつ**に分けて取り、今何ページ目かも管理する |

`paginate()` の結果は「ページ付きの一覧」で、`foreach` で回せます（見た目は `get()` とほぼ同じ使い方）。

### 3.4 `flux:pagination` … ページ送りボタン

```blade
@if ($stories->hasPages())
    <flux:pagination :paginator="$stories" class="mt-6" />
@endif
```

- `hasPages()` … 「**2ページ目以降があるか？**」を判定
- 10件以下なら `false` → ページ送りは出ない
- 11件以上なら `true` → 「1 2 次へ」のようなボタンが出る

お題一覧も同じ書き方です（変数名は `$images`）。

### 3.5 マイページだけ `resetPage()` が必要な理由

```php
public function updatedSearch(): void
{
    $this->resetPage();
}

public function updatedStatusFilter(): void
{
    $this->resetPage();
}
```

ステップ14で付けた検索・絞り込みと組み合わせるときの工夫です。

**問題のシナリオ:**

1. 投稿が11件ある
2. ユーザーが2ページ目を見ている
3. 検索ボックスに文字を入れる
4. 結果が1件だけになった
5. でも画面は「2ページ目」のまま → **一覧が空に見える！**

だから検索やステータスを変えたら **`resetPage()` で1ページ目に戻す** のが安全です。

お題一覧には検索・絞り込みがないので、`resetPage()` は**不要**です。

### 3.6 マイページとお題一覧の比較

| 項目 | マイページ | お題一覧 |
| --- | --- | --- |
| 取るデータ | 自分のストーリー | お題画像（`Image`） |
| `WithPagination` | 使う | 使う（同じ） |
| `paginate(10)` | 使う | 使う（同じ） |
| `flux:pagination` | 使う | 使う（同じ） |
| `resetPage()` | 必要（検索・絞り込みあり） | 不要 |
| ログイン | 必須 | 不要（誰でも見られる） |

**原理は同じ**で、データの種類といくつかの細かい違いだけです。

## 4. 理解度チェック問題（4択・解答つき）

まずは選択肢を見て、自分で答えを考えてみましょう。解答と中学生レベルの解説は各問のすぐ下にあります。

### Q1. `use WithPagination;` をコンポーネントに書く理由は？

- A. データベースのテーブルを自動で作るため
- B. Livewire でページ送り（次のページ・前のページ）ができるようにするため
- C. ログインしていない人を弾くため
- D. 検索ボックスを表示するため

**正解：B**

`WithPagination` は Livewire のトレイトで、ページ送り機能を付けます。`nextPage()`、`previousPage()`、`gotoPage()` や `flux:pagination` のボタンが動くようになります。

引っかけ：A はマイグレーションの話、C は `auth` ミドルウェアの話、D は検索UIの話で、どれも `WithPagination` とは無関係です。

### Q2. `->get()` を `->paginate(10)` に変えると何が変わる？

- A. データを10件ずつに分けて取り、ページ送りできるようになる
- B. データを10件だけ削除する
- C. 10件未満のときエラーになる
- D. 10秒ごとに自動でページが切り替わる

**正解：A**

- `get()` … 全部取る
- `paginate(10)` … 10件ずつに分けて取り、何ページ目かも管理する

投稿が増えても一度に10件だけ読み込むので、画面もデータベースも軽くなります。

引っかけ：B は削除ではない、C は10件未満でも普通に動く（ページ送りは出ないだけ）、D は時間の話で無関係です。

### Q3. マイページの `updatedSearch()` で `$this->resetPage();` を呼ぶ理由は？

- A. 検索語を空にするため
- B. 検索や絞り込みを変えたとき、2ページ目のままだと結果が空に見えることがあるので、1ページ目に戻すため
- C. ストーリーを削除するため
- D. お題一覧ページへ移動するため

**正解：B**

2ページ目にいる状態で検索すると、結果が1件だけになっても「2ページ目」を見続けると一覧が空に見えることがあります。`resetPage()` は「**1ページ目に戻す**」命令です。

ステータス（`updatedStatusFilter()`）を変えたときも同じ理由で呼びます。

引っかけ：A は検索語を消す処理ではない、C は `delete()` の話、D はリダイレクトの話です。

### Q4. 次のコードの役割は？

```blade
@if ($images->hasPages())
    <flux:pagination :paginator="$images" class="mt-6" />
@endif
```

- A. お題が0件のときだけページ送りを表示する
- B. 2ページ目以降があるときだけページ送りを表示する
- C. ログインしている人だけページ送りを表示する
- D. 完成ストーリーがあるお題だけページ送りを表示する

**正解：B**

`hasPages()` は「**2ページ目以降があるか？**」を判定します。

- 10件以下 → `false` → ページ送りなし
- 11件以上 → `true` → ページ送りあり

0件のときは `@else` の一覧ブロック自体が表示されないので、この `@if` には到達しません。

引っかけ：A は逆（0件のときは一覧すら出ない）、C・D はログインやストーリー数とは無関係です。

### Q5. お題一覧とマイページのページネーションについて、正しいのは？

- A. 原理は同じだが、お題一覧には検索がないので `resetPage()` は不要
- B. お題一覧だけ `WithPagination` を使い、マイページは使わない
- C. マイページは1ページ5件、お題一覧は1ページ20件に決まっている
- D. お題一覧はログイン必須で、マイページは誰でも見られる

**正解：A**

両方とも `WithPagination` + `paginate(10)` + `flux:pagination` という**同じ原理**です。違いはデータの種類と、マイページだけ検索・絞り込みがあるので `resetPage()` が必要な点です。

引っかけ：B は逆（両方使う）、C はどちらも10件、D はログインの要否が逆です。

### 5問のつながり（まとめ）

```
WithPagination でページ送り機能（Q1）
→ paginate(10) で10件ずつ取得（Q2）
→ 検索変更時は resetPage()（Q3）
→ 2ページ以上あるときだけ UI 表示（Q4）
→ お題一覧は同じ原理で、resetPage は不要（Q5）
```

この5つがつながって「使いやすいページネーション」ができています。

## 5. 動作確認の方法

```bash
composer run dev
```

### マイページ

1. ログインして、自分のストーリーを11件以上用意する
2. マイページを開く →「Showing 1 to 10 of 11 results」とページ番号が出る
3. 2ページ目に移動できる
4. 検索やステータスを変える → 1ページ目に戻る

### お題一覧

1. お題を11件以上用意する（管理者が投稿）
2. トップページを開く → 10件表示 + ページ送り
3. 2ページ目に移動できる

テスト:

```bash
php artisan test --filter=MyPageTest
php artisan test --filter=HomePageTest
```

# Livewire のページネーションをやさしく理解する

文倉（fumikura）のお題一覧・マイページで使っている「ページ送り」の仕組みを、専門用語をできるだけ使わずに説明します。

---

## 1. ページネーションって何？

本が 100 ページあるとき、**一度に 1 ページだけ**見る、というイメージです。

文倉のお題一覧は、お題がたくさんあっても **一度に 10 件だけ**表示して、「次へ」ボタンで次の 10 件を見せています。

- 1 ページ目 … 1 番目〜10 番目のお題
- 2 ページ目 … 11 番目〜20 番目のお題
- …という感じです。

---

## 2. 普通のページ移動との違い

### 昔ながりのやり方（ページ全体の再読み込み）

1. 「2 ページ目」を押す
2. 画面が**いったん真っ白**になる
3. ヘッダーやロゴも含めて、**ページ全体**が読み直される

### Livewire のやり方（文倉が今使っている）

1. 「2 ページ目」を押す
2. 画面全体はそのまま
3. **お題の一覧部分だけ**が、新しい 10 件に入れ替わる

### レストランで例えると

| やり方 | イメージ |
| --- | --- |
| 昔ながり | 店ごと建て替え |
| Livewire | **メニュー表だけ**差し替え |

---

## 3. Livewire は具体的に何をしている？

文倉のお題一覧では、だいたい次の流れです。

1. **最初にサイトを開く**  
   サーバー（文倉のプログラムが動いているコンピュータ）が、お題を 10 件取って画面を作る。

2. **「2 ページ目」を押す**  
   ブラウザがサーバーに「2 ページ目ください」と**こっそり**連絡する。  
   このとき、画面は真っ白にならない。

3. **サーバーがまた 10 件取る**  
   データベース（データの倉庫）から、11 番目〜20 番目だけ取り出す。

4. **一覧部分だけ差し替える**  
   作り直した部分だけブラウザに届いて、**パッと**入れ替わる。

「非同期で動いている」とは、**ページ全体を読み直さず、裏でデータを取りに行って、必要な部分だけ更新している**、という意味です。

---

## 4. 文倉のプログラムではどこでやっている？

### データを 10 件ずつ取る

```php
'images' => $this->imagesQuery()->paginate(10),
```

「全部まとめて取る」のではなく、「今のページに必要な 10 件だけ取る」という意味です。

### ページ送りの機能を付ける

```php
use Livewire\WithPagination;
```

Livewire に「今何ページ目か」を覚えさせて、ページ送りボタンを動かすための機能です。

### ページ送りボタンを表示する

```blade
<flux:pagination :paginator="$images" />
```

「前へ」「次へ」「2」などのボタンです。押すと Livewire が裏でサーバーとやり取りします。

## 5. React との違い（かみ砕き版）

ここでいう **React** は、画面の動きを **JavaScript（ブラウザ側のプログラム）** で作る、よくあるやり方の代表例です。

| | Livewire（文倉） | React よくある作り方 |
| --- | --- | --- |
| 頭脳はどこ？ | **サーバー（PHP）** | **ブラウザ（JavaScript）** と **サーバー（API）** の両方 |
| 誰がデータを取る？ | サーバーが DB から直接取る | ブラウザがサーバーに「データちょうだい」と頼む |
| 誰が画面を直す？ | サーバーが HTML を作って返す | ブラウザが受け取ったデータで画面を描き直す |
| 作るもの | PHP と Blade だけでだいたい完結 | 画面用 JS + データ用 API の **2 セット** になりがち |

### 例え：宿題の出し方

**Livewire**

- 先生（サーバー）が問題を選んで、答え用紙（HTML）ごと渡す
- 次のページが欲しくなったら、また先生に「次の問題ください」と言う
- **先生一人でだいたい完結**

**React よくある作り方**

- 先生は「問題データだけ」を JSON で渡す専門係（API）
- 生徒（ブラウザの JavaScript）がそれを受け取って、自分でノートに書いて見せる
- **先生側と生徒側、両方の仕事が必要**

---

## 6. Livewire の良いところ

1. **書く場所が 1 つで済む**  
   データの取り方も、画面の見せ方も、PHP 側にまとまる。

2. **ページ送りが簡単**  
   「10 件ずつ取る」と「ページ送りボタン」を付けるだけで、裏の通信は Livewire が面倒を見てくれる。

3. **ログイン情報をそのまま使える**  
   「誰がログインしているか」はサーバーが知っているので、マイページのように「自分の投稿だけ」も PHP のまま書ける。

4. **画面がチラつきにくい**  
   ページ全体ではなく、一覧部分だけ換わる。

5. **テストしやすい**  
   「2 ページ目を押したら次の 10 件が出る」を、ブラウザを開かなくてもプログラム側で確認できる。

---

## 7. Livewire が向かないこと（超ざっくり）

- ゲームみたいに **1 秒に何十回も** 画面が変わるもの
- 超凝ったアニメーションだけで画面を組み立てるもの

文倉のような「一覧を見る・並び替える・ページを送る」には、Livewire はとても向いています。

---

## 8. 用語ミニ辞典

| 用語 | やさしい意味 |
| --- | --- |
| サーバー | 文倉のプログラムが動いているコンピュータ。データを取って画面を作る係。 |
| ブラウザ | Chrome など、自分がサイトを見るアプリ。 |
| PHP | サーバー側で動くプログラムの言語。文倉の本体。 |
| JavaScript | ブラウザ側で動くプログラムの言語。React はこれを使う。 |
| HTML | ブラウザに表示するための「画面の設計図」。 |
| データベース（DB） | お題やストーリーなどのデータを保存しておく倉庫。 |
| 非同期 | 画面全体を止めずに、裏でこっそり処理すること。 |
| API | ブラウザが「データください」と頼むための窓口。 |
| React | 画面の動きを JavaScript で作る、よく使われるやり方の名前。 |

---

## 9. 一文でまとめると

**Livewire のページネーション**は、

> 「次のページください」とサーバーに頼む → サーバーが 10 件取ってくる → **一覧だけパッと差し替える**

という動きです。

**React よくある作り方**は、

> ブラウザ（JavaScript）がデータをもらって、自分で画面を組み立て直す

という動きで、**分担が増える**のが大きな違いです。

文倉は Laravel 1 つで画面まで作れる Livewire 向きのサイト、と覚えておくとイメージしやすいです。
